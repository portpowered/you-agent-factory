# Provider Session Golden Contract

## Purpose

Provider tests must validate the system against representative provider
execution output, not only hand-constructed canonical objects. Sanitized
goldens preserve the native response shape emitted by an execution and the
public metadata the system is required to derive from it.

## Location

```text
docs/temp/functional/provider-sessions/
  <provider>/
    <case>/
      manifest.json
      request.json
      process.json
      stdout.jsonl
      stderr.txt
      expected-provider-session.json
      expected-response-events.ndjson
      expected-invocation-result.json
```

`stdout.jsonl` may be `stdout.json` or `stdout.txt` when that is the provider's
real output shape. The manifest declares the media type and decoder.

The implementation must add a narrow `.gitignore` exception so this root is
tracked despite the general `docs/temp/**` rule.

## `manifest.json`

Required fields:

```json
{
  "schemaVersion": 1,
  "id": "codex-message-tool-success",
  "provider": "codex",
  "providerVersion": "captured-or-fixture-version",
  "fidelityClass": "partial-stream",
  "case": "success",
  "stdoutFile": "stdout.jsonl",
  "stderrFile": "stderr.txt",
  "requestFile": "request.json",
  "processFile": "process.json",
  "expectedProviderSessionFile": "expected-provider-session.json",
  "expectedResponseEventsFile": "expected-response-events.ndjson",
  "expectedInvocationResultFile": "expected-invocation-result.json",
  "normalizedFields": [
    "eventId",
    "recordedAt",
    "factorySessionId",
    "runId"
  ],
  "sanitizerVersion": 1,
  "source": "sanitized-provider-exec"
}
```

Allowed fidelity classes are `full-stream`, `partial-stream`,
`snapshot-only`, and `final-only`. A provider may only claim capabilities
proven by its golden cases.

## Captured process metadata

`process.json` records the execution facts needed to reproduce normalization:

- argument vector with secrets removed;
- selected model and provider;
- exit code or termination signal;
- whether stdout/stderr were streams;
- working-directory role, never an absolute host path;
- timeout/cancellation classification;
- expected terminal error class.

It must not contain the complete host environment.

## Comparison pipeline

1. Load and validate the manifest.
2. Run the fixture sanitizer and reject forbidden material.
3. Create the provider request from `request.json`.
4. Feed raw stdout/stderr/exit metadata to the production provider adapter
   through an injected external process edge.
5. Invoke the root-built application through the public test entrypoint.
6. Collect the public Provider Session metadata, FactoryResponseEvents, and
   terminal invocation result.
7. Normalize only the fields listed in `normalizedFields`.
8. Compare canonical JSON structurally; do not compare whitespace.
9. Verify event ordering, item correlation, provider provenance, fidelity
   claims, terminal state, and redaction independently of the whole-file
   comparison.

Expected output must not be generated by calling the mapper under test during
the assertion. Golden updates use a separate explicit command and require:

```sh
UPDATE_FUNCTIONAL_GOLDENS=1
```

Normal CI fails on drift and never rewrites files.

## Required provider cases

Every supported provider:

- [ ] successful text response;
- [ ] normalized non-zero failure;
- [ ] timeout or cancellation;
- [ ] stable Provider Session identity when the provider supplies one;
- [ ] absence of fabricated Provider Session identity when it does not;
- [ ] accurate capability and fidelity declaration;
- [ ] CLI output and API response-event projections derived from the same
  canonical result.

Providers claiming streaming:

- [ ] message lifecycle;
- [ ] message delta or truthful snapshot behavior;
- [ ] tool start and completion when supported;
- [ ] partial stream followed by successful terminal output;
- [ ] malformed record handling;
- [ ] stream ending before terminal output.

Provider-specific minimums:

| Provider | Required golden cases |
| --- | --- |
| Codex | text success, tool lifecycle, partial stream, session identity, structured failure, timeout |
| Claude | full text stream, tool lifecycle, session identity, structured failure, timeout |
| Cursor | text success, session identity, malformed record, structured failure, timeout |
| OpenCode | structured snapshot success, final-only fallback, structured failure, timeout |
| Gemini | text success, structured failure, rate limit, timeout |
| Kiro | text success, structured failure, auth failure, timeout |
| Pi | text success, structured failure, timeout |
| Agy | final-only success, structured failure, timeout |

## Sanitization gate

Reject:

- access tokens, API keys, cookies, bearer headers, and credential-like values;
- user home directories and absolute workspace paths;
- private repository URLs;
- raw environment dumps;
- unbounded prompts or outputs unrelated to the case;
- provider account identifiers not required by the public contract.

Retain sanitized structural values needed to test parsing, including stable
fake session IDs, tool-call IDs, item IDs, usage counts, finish reasons, and
error codes.

## Golden metadata in the visualization

For every golden-backed top-level test, `functional-tests.md` shows:

| Field | Source |
| --- | --- |
| Provider | `manifest.json.provider` |
| Case | `manifest.json.case` |
| Fidelity | `manifest.json.fidelityClass` |
| Golden ID | `manifest.json.id` |
| Test description | Go doc comment |
| Source | Go test declaration |
| Fixture | manifest path |

The visualization fails when a test references a missing manifest or when two
manifests declare the same provider/golden ID.
