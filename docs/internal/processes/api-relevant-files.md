# API Relevant Files

Use this map when changing the public REST contract.

- `api/openapi-main.yaml` is the authored OpenAPI entrypoint. Register new component fragments under `components.schemas` here.
- `api/components/schemas/api/` contains API request/response fragments.
- `api/components/schemas/data-models/` contains customer-facing factory and work data model fragments.
- Factory orchestrator identity lives in `api/components/schemas/data-models/FactoryOrchestrator*.yaml`; wire through `pkg/interfaces/factory_orchestrator.go`, `pkg/config/factory_orchestrator_mapping.go`, `pkg/factory/validation/orchestrator.go`, and project read-time PETRI defaults via `config.ProjectEffectiveOrchestratorForAPIRead` from `pkg/replay/generated_factory.go`.
- Factory session runtime projections live in `api/components/schemas/api/FactorySession*.yaml`; map live sessions through `pkg/factorysessions/projection.go` and `pkg/factorysessions/enablement.go`, with service assembly in `pkg/service/runtime_sessions.go` and transport in `pkg/api/handlers_factory.go`.
- JavaScript checkpoint refs and internal checkpoint bundles live in `api/components/schemas/data-models/FactoryArtifact*.yaml`, `api/components/schemas/api/FactorySessionResult.yaml`, `api/components/schemas/api/FactorySessionPartialResult.yaml`, and `api/components/schemas/events/payloads/JavaScriptCheckpointRefEventPayload.yaml`; keep raw VM bodies in `pkg/interfaces/javascript_checkpoint.go` and project public refs through `pkg/factorysessions/checkpoints.go`, with world replay in `pkg/factory/projections/world_state.go`.
- Shared dispatch and artifact runtime projections live in `api/components/schemas/data-models/FactoryDispatch*.yaml` and `api/components/schemas/data-models/FactoryArtifact.yaml`; map Petri dispatches from `pkg/factorysessions/dispatch_projection.go` via engine snapshots, JavaScript dispatches/artifacts from `pkg/interfaces/factory_dispatch_projection.go`, and expose both through `FactorySessionRuntime.dispatches` / `artifacts` in `pkg/factorysessions/projection.go`.
- `api/openapi.yaml`, `pkg/api/generated/server.gen.go`, `pkg/generatedclient/client.gen.go`, and `ui/src/api/generated/openapi.ts` are generated by `make generate-api`.
- `pkg/api/contracttests/` contains OpenAPI authoring, bundled-contract, and generated-type smoke tests for public API changes.
- Adding a new OpenAPI operation updates `factoryapi.ServerInterface`; add or update the matching `pkg/api` handler before running package tests.
- Managed-runtime discovery and inspect projection live in `pkg/localmodels/catalog.go` and `pkg/localmodels/managed_runtime.go`; wire runtime cache and source resolver inputs through `localmodels.CatalogOptions` from `pkg/service/model_catalog.go`.
- Managed-runtime pull projection and outcome normalization live in `pkg/localmodels/pull_lifecycle.go` and `pkg/localmodels/catalog.go` (`PullModelWithOptions`); API transport mapping for `managedRuntimePull` belongs in `pkg/apisurface/managed_runtime.go`; pull logging and `managed_runtime.pull.*` metrics belong in `pkg/service/model_catalog.go`.
- Managed-runtime factory dependency validation lives in `pkg/factory/validation/managed_runtime_dependency.go`; readiness projection for packaged and authored factories lives in `pkg/localmodels/runtime_dependency.go`; consume validation through `pkg/config/config_validator_topology.go` canonical structural validation.
- Managed-runtime invocation readiness gating lives in `pkg/localmodels/invocation_readiness.go` and `pkg/apisurface/managed_runtime_invocation.go`; wire through `InvokeModel` in `pkg/service/model_catalog.go` and `localmodels.Manager.execute` in `pkg/localmodels/runtime.go`; classify model-event failures via `modelEventErrorClass` in `pkg/service/factory_runtime_state.go`.
- Dashboard current-factory normalization for model-invoke authoring lives in `ui/src/api/factory-definition/api.ts` with shared decode helpers in `api.decode-helpers.ts` and model-operation/binding decoders in `api.model-invoke.ts`; keep `WORKER_KEYS.operations`, `WORKSTATION_KEYS.operation` / `operationBindings`, and `MODEL_INVOKE` in `WORKSTATION_TYPE_VALUES` aligned with the generated OpenAPI `Factory` schema when extending model-invoke fields.
