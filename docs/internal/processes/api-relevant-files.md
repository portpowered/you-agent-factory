# API Relevant Files

Use this map when changing the public REST contract.

- `api/openapi-main.yaml` is the authored OpenAPI entrypoint. Register new component fragments under `components.schemas` here.
- `api/components/schemas/api/` contains API request/response fragments.
- `api/components/schemas/data-models/` contains customer-facing factory and work data model fragments.
- Factory orchestrator identity lives in `api/components/schemas/data-models/FactoryOrchestrator*.yaml`; wire through `pkg/interfaces/factory_config.go`, `pkg/config/factory_config_mapping_internal.go`, and `pkg/factory/validation/validate.go` orchestrator targets. Keep flattened/exported factories free of default PETRI orchestrator blocks via `FactoryConfigMapper.Flatten`; use `config.ProjectEffectiveOrchestratorForAPIRead` only on explicit read surfaces that need compatibility projection, not `replay.GeneratedFactoryFromRuntimeConfig`.
- JavaScript orchestrator source loading and resolution belong under `pkg/orchestrators/javascript/source` (see `docs/internal/development/plans/dynamic-workflows/dynamic-workflow-design.md`). Lookup order: project `.claude/workflows`, `~/.you-agent-factory/workflows`, package-relative `factory/workflows`, named JavaScript factories, then explicit factory lookup when requested. Normalize API, CLI, MCP, and website source requests through `pkg/apisurface/workflow_source.go` (CLI re-export in `pkg/cli/workflowsource/normalize.go`) until contract repair moves normalization beside Factory Session start surfaces. Transitional root `pkg/workflowsource/` is **stale Batch 001** — not the intended final ownership boundary.
- JavaScript orchestrator source validation belongs under `pkg/orchestrators/javascript/validation` (static parse via `github.com/tdewolff/parse/v2/js`, no execution). File-backed `.js` and supported `.ts` sources load before `ValidateLoaded` with stable `SourceHash`, TypeScript syntax stripping, and authored-line remapping. Integrate factory validation through `pkg/factory/validation/validate.go` for inline source plus orchestrator metadata/argsSchema checks, and `pkg/factory/validation/WorkflowSourceTargets` with `validation.Options.WorkflowSourceReader` for file-backed `sourceRef` reads from `pkg/factory/validationentry/api.go`. Transitional root `pkg/workflowvalidation/` is **stale Batch 001**.
- JavaScript orchestrator policy defaults, validation, stable hashing, and capability denial belong under `pkg/orchestrators/javascript/policy`. Normalize API, CLI, MCP, and website policy requests through `pkg/apisurface/workflow_policy.go`. Integrate factory defaultPolicy validation through `pkg/factory/validation/validate.go` and session runtime policy hash/budget projection through `pkg/factorysessions/projection.go`. Transitional root `pkg/workflowpolicy/` is **stale Batch 001**.
- JavaScript orchestrator result validation, artifact URI parsing, and `FactorySessionResult.primaryResult` / `SESSION_RESULT_UPDATED` projection belong under `pkg/orchestrators/javascript/result`. Normalize API, CLI, MCP, and website result-shape checks through `pkg/apisurface/workflow_result.go`. Integrate terminal session result reads through `pkg/factorysessions/checkpoints.go` and replay through `pkg/factory/projections/world_state.go`. Transitional root `pkg/workflowresult/` is **stale Batch 001**.
- JavaScript orchestrator durable session state (source snapshots, phase summaries, checkpoints, artifacts, replay indexes) belongs under `pkg/orchestrators/javascript/store`. Project store reads through session runtime and replay surfaces; raw VM state stays outside general session snapshots.
- JavaScript orchestrator preview preparation belongs under `pkg/orchestrators/javascript/preview` and must use **Factory preview** or **Factory Session preview** semantics, not a standalone workflow-preview product surface. Transitional `POST /workflow-previews`, `pkg/workflowpreview/`, `pkg/apisurface/workflow_preview.go`, CLI `you workflow preview`, MCP `pkg/mcp/workflow/preview.go`, and website `ui/src/api/workflow-preview/` + `ui/src/features/workflow-preview/` are **stale Batch 001** — contract repair must align public preview changes with Factory or Factory Session surfaces before downstream API, CLI, MCP, or UI skeleton wiring.
- JavaScript orchestrator start-time checks (source resolution, validation, and policy enforcement before dispatch) belong under `pkg/orchestrators/javascript/{source,validation,policy}` and must wire through Factory Session execution start surfaces (`POST /factory-sessions/async`, `POST /factory-sessions/sync`, and related durable start/read/control routes below) via `pkg/factorysessionexecution/` and `pkg/apisurface/factorysession/` — not through transitional preview-only routes or root `pkg/workflow*` helpers (**stale Batch 001**).
- Dynamic workflow public REST contract repair: author changes in `api/openapi-main.yaml` and `api/components/`, normalize at `pkg/apisurface/`, implement handlers and tests in `pkg/api/`, regenerate Go and TypeScript clients with `make generate-api`, and run `make api-smoke` when feasible after public REST contract changes.
- Factory session runtime projections live in `api/components/schemas/api/FactorySession*.yaml`; map live sessions through `pkg/factorysessions/projection.go` and `pkg/factorysessions/enablement.go`, with service assembly in `pkg/service/runtime_sessions.go` and transport in `pkg/api/handlers_factory.go`.
