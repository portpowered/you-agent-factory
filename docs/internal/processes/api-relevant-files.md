# API Relevant Files

Use this map when changing the public REST contract.

- `api/openapi-main.yaml` is the authored OpenAPI entrypoint. Register new component fragments under `components.schemas` here.
- `api/components/schemas/api/` contains API request/response fragments.
- `api/components/schemas/data-models/` contains customer-facing factory and work data model fragments.
- Factory orchestrator identity lives in `api/components/schemas/data-models/FactoryOrchestrator*.yaml`; wire through `pkg/interfaces/factory_config.go`, `pkg/config/factory_config_mapping_internal.go`, and `pkg/factory/validation/validate.go` orchestrator targets. Keep flattened/exported factories free of default PETRI orchestrator blocks via `FactoryConfigMapper.Flatten`; use `config.ProjectEffectiveOrchestratorForAPIRead` only on explicit read surfaces that need compatibility projection, not `replay.GeneratedFactoryFromRuntimeConfig`.
- JavaScript orchestrator source loading and resolution belong under `pkg/orchestrators/javascript/source` (see `docs/internal/development/plans/dynamic-workflows/dynamic-workflow-design.md`). Lookup order: project `.claude/workflows`, `~/.you-agent-factory/workflows`, package-relative `factory/workflows`, named JavaScript factories, then explicit factory lookup when requested. Normalize API, CLI, MCP, and website source requests through `pkg/apisurface/workflow_source.go` (CLI re-export in `pkg/cli/workflowsource/normalize.go`). Durable Factory Session start paths resolve sources through `pkg/factorysessionexecution/start_source.go` (`ResolveStartSource`, `StartSourceContext`). Root `pkg/workflowsource/` is a **deprecated Batch 001 compatibility shim** (`compat.go` forwarding to orchestrator ownership) — core runtime/API imports must use `pkg/orchestrators/javascript/source` directly.
- JavaScript orchestrator source validation belongs under `pkg/orchestrators/javascript/validation` (static parse via `github.com/tdewolff/parse/v2/js`, no execution). File-backed `.js` and supported `.ts` sources load before `ValidateLoaded` with stable `SourceHash`, TypeScript syntax stripping, and authored-line remapping. Integrate factory validation through `pkg/factory/validation/validate.go` for inline source plus orchestrator metadata/argsSchema checks, and `pkg/factory/validation/WorkflowSourceTargets` with `validation.Options.WorkflowSourceReader` for file-backed `sourceRef` reads from `pkg/factory/validationentry/api.go`. Root `pkg/workflowvalidation/` is a **deprecated Batch 001 compatibility shim** — core runtime/API imports must use `pkg/orchestrators/javascript/validation` directly.
- JavaScript orchestrator policy defaults, validation, stable hashing, and capability denial belong under `pkg/orchestrators/javascript/policy`. Normalize API, CLI, MCP, and website policy requests through `pkg/apisurface/workflow_policy.go`. Root `pkg/workflowpolicy/` is a **deprecated Batch 001 compatibility shim** — core runtime/API imports must use `pkg/orchestrators/javascript/policy` directly.

- JavaScript orchestrator simple workflow execution belongs under `pkg/orchestrators/javascript/runtime` (`Run`, `RunWithTimeout`, `Request`, `Outcome`, `Hooks`, `ChildExecutor`, `ChildExecutorFactory`). The default boundary uses embedded `github.com/dop251/goja`, injects structured `args`/`meta`, progress/state host primitives (`phase`, `log`, `workflow.log`, `workflow.artifact`, `workflow.checkpoint`, `workflow.budget`), `agent.run`, `parallel`, and `pipeline` (all child work routes through `ChildExecutor`; default `FakeChildExecutor`, replaceable via `Hooks.NewChildExecutor`), and `workflow.final` (no filesystem, process, network, or shell globals), supports returned finals and `workflow.final` (with `workflow.final` taking precedence when both are present), and validates successful terminal values with `pkg/orchestrators/javascript/result.ValidateTypedValue` before `OnResult` or `OK=true` (invalid finals return `WORKFLOW_RUNTIME_INVALID_RESULT` with `[workflow.result.*]` validation context). Host primitive calls append typed ordered `Outcome.Records` (`RuntimeRecord` with phase/log/artifact/checkpoint/budget/child_dispatch payloads) suitable for later factory session event mapping; `workflow.artifact` returns deterministic `you-artifact://sessions/{session_id}/artifacts/{artifact_id}` URIs via `pkg/orchestrators/javascript/result.FormatArtifactURI` and may invoke `Hooks.OnArtifact`. `agent.run` resolves a Promise, routes through `ChildExecutor`, and appends queued/running/completed `child_dispatch` records with dispatch-like metadata (`dispatchId`, `promptDigest`, `schemaDigest`, `providerSessionRef`, `executionMode=fake`) plus a deterministic structured child result for later `Dispatch` mapping. `parallel` accepts an array of agent run specs or async functions, pre-reserves dispatch identities in input order, enforces `policy.maxAgents` before fanout via `denyChildSlots`, validates each child request through `pkg/orchestrators/javascript/policy.ValidateChildRequest` before fake dispatch, schedules fake child execution with `policy.concurrency`, returns results in input order, and represents per-item failures with `FAILED` child results plus `child_dispatch` records (`prompt` prefixes `fail:` simulate deterministic fake child failure in tests; policy-denied children fail before dispatch records are emitted). `pipeline(items, worker, next?)` runs staged fake child work per item in input order (worker then optional next), returns per-item `{ index, item, status, stages[] }` results with stage success/failure details, passes each stage's resolved result into the next stage for the same item, and routes stage `agent.run` calls through the same `ChildExecutor` path as `agent.run` and `parallel`. Pre-execution checks call `pkg/orchestrators/javascript/validation.Validate` on the IIFE-wrapped executable source (with authored-line remapping) before `goja` execution; shape/syntax issues return `WORKFLOW_RUNTIME_PRE_EXECUTION_INVALID` and forbidden host-access patterns return `WORKFLOW_RUNTIME_DENIED_CAPABILITY` (embedding `[workflow.source.forbiddenHostAccess]` validation context) without invoking result/artifact hooks. Execution failures return `WORKFLOW_RUNTIME_SCRIPT_ERROR` (preserving JavaScript `Error.message` via `javascriptExceptionMessage`, including ordered `Outcome.Records` collected before the failing host call) or `WORKFLOW_RUNTIME_UNRESOLVED_FINAL` when no terminal value is present; context cancellation and deadline timeout return `WORKFLOW_RUNTIME_CANCELED` and `WORKFLOW_RUNTIME_TIMEOUT` via `watchContext`/`vm.Interrupt` without invoking result/artifact hooks. Child host calls enforce `allowedModels`, `allowedReasoningEfforts`, `allowedCommands`, sandbox mode, writable roots, network, and per-request concurrency through `ValidateChildRequest`; `workflow.artifact` enforces `maxArtifactBytes` before hooks or artifact records. Fixture-backed runtime tests live beside the package (`runtime/testdata/*.workflow.js`, `runtime/runtime_test.go`, `runtime/host_primitives_test.go`, `runtime/host_children_test.go`, `runtime/host_pipeline_policy_test.go`); prove cancellation, timeout, host-access denial, policy-denied child/progress primitives, invalid terminal values (functions, unresolved promises, host-path JSON), progress/state primitive records, fake `agent.run` child dispatch records, bounded-concurrency `parallel` fanout, staged `pipeline` item ordering, and replaceable child execution through `Hooks.NewChildExecutor` in focused runtime tests rather than transport surfaces. Child host primitive implementations are consolidated in `runtime/host_children.go` to stay within the `pkg-file-count` package limit.
