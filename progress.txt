## Codebase Patterns
- Visual group layout metadata lives in `layout.groups[]` on the OpenAPI `FactoryLayout` schema; backend pruning/validation is in `pkg/factory/validation/layout.go` (`pruneLayoutGroups`, `layoutGroupTargets`).
- Frontend layout save/validation should mirror edge layout helpers in `ui/src/features/factory-graph-editor/lib/layout/factory-graph-layout-validation.ts`; pass full `FactoryGraphTopology` to `preparePendingFactoryLayoutForSave` and `projectFactoryLayoutValidationTargets`.
- `factoryLayoutFromDefinition` clones the full layout (including groups); group round-trips through `applyFactoryGraphPendingEdits` when `pendingLayout.groups` changes set `layoutDirty`.
- Visual group editor operations live in `lib/layout/visual-groups/factory-graph-layout-groups.ts` with undo commands (`create-group`, `update-group`) in `factory-graph-layout-commands.ts`; UI components live under `components/flow/visual-groups/`; wire through `useFactoryGraphVisualGroupEditor` and render behind nodes via `FactoryGraphVisualGroupLayer` inside React Flow.
- When workflow-activity imports new factory-graph-editor internal paths, add matching entries to `ui/scripts/feature-cross-import-allowlist.mjs`; fixing file-count guards can surface previously skipped boundary checks in `bun run lint`.
- Approved v1 group colors are token keys in `FACTORY_LAYOUT_GROUP_COLOR_TOKENS` (`primary`, `info`, `success`, `warning`, `outline`); map to CSS via `factoryLayoutGroupColorCssVariable` / `factoryLayoutGroupColorSurfaceCssVariable`.
- Group creation at viewport center should reuse `viewportCenterFromPlacementViewport` from `graph-editor-add-node-placement.ts` (updated by canvas `onMoveEnd` / `onInit` through `addControls.updatePlacementViewport`).
- Flat v1 group membership lives on `layout.groups[].nodeIds`; use `addNodeToFactoryLayoutGroup` / `removeNodeFromFactoryLayoutGroup` (removes node from other groups when reassigning). Expose canvas options via `factoryLayoutGroupCanvasNodeOptions(topologyNodes)` on layout controls.
- Group move uses `move-visual-group` layout commands (bounds + member node moves in one undo step); resize uses `update-group`; delete uses `update-group` with `to: absent` and restore-on-undo via `addFactoryLayoutGroup` when the group id is missing. Canvas drag/resize lives in `FactoryGraphVisualGroupLayer` with pointer sessions mirroring `FactoryGraphEdgeWaypointLayer`.
- Recoverable layout group warnings use `layoutValidationWarningMessages` on FACTORY-type `severity: "warning"` targets; surface shows them under `noticeLayoutWarningTitle` while draft/topology errors stay in the danger validation notice. Invalid group bounds surface via `isValidFactoryLayoutGroupBounds` in selected-group controls.
- Visual group save/reload browser verification: Storybook harness `factory-graph-visual-group-save.stories.tsx` plus `bun run storybook:factory-graph-visual-group-save-check` (builds Storybook static first).
