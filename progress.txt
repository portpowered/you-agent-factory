## Codebase Patterns
- Use `workflowruntime.Hooks.NewChildExecutor` with `ChildRecordSink` to swap fake vs `live-provider` child execution without changing workflow JS source.
- `ChildExecutor.Execute` accepts the bounded workflow `context.Context` from `workflowruntime.Run`; live provider bridges must pass it through to `Provider.Infer` instead of `context.Background()`.
- Select live child execution via `StartRequest.Runtime.ChildExecutorMode = "live-provider"` and configure `JavaScriptRuntimeServiceConfig.Provider`.
- Durable dispatch inspection for JavaScript children flows through `ProjectRuntimeExecutionRecords` into `DispatchSummary` plus `DispatchJavaScriptProjection.ExecutionMode`.
- `ProjectRuntimeExecutionRecords` also projects ordered `DispatchStatusTransitions` per dispatch ID and child output artifacts from completed `ChildDispatchRecord.ArtifactRef`.
- Failed child dispatches persist `FailureReason`, `FailureMessage`, and optional `FailureErrorClass` on terminal `ChildDispatchRecord` rows; `dispatchFailureDetailFromChildRecord` maps them to `DispatchFailureDetail`.
- `projectRuntimeSessionState` applies `applyRuntimeExecutionRecordProjection` on workflow failure when `outcome.Records` is non-empty so failed child dispatches remain inspectable.
- `workflowruntime.Run` attaches emitted runtime records to terminal promise-rejection and invalid-result failures, not only synchronous script errors.
- `GetDispatch` on the JavaScript runtime service exposes `StatusTransitions` and `ArtifactIDs` from the runtime projection state.
- Default JavaScript runtime durable sessions keep fake child execution when no runtime override is provided.
- Select explicit fake child execution via `StartRequest.Runtime.ChildExecutorMode = "fake"` even when the service default is `live-provider`; request-level mode wins over `JavaScriptRuntimeServiceConfig.ChildExecutorMode`.
- Record deferred CLI/MCP/website follow-ups in `docs/internal/development/plans/dynamic-workflows/follow-up-cell-live-provider-dispatch-bridge-deferred.md` instead of widening the bridge lane.
- When `make pkg-file-count` fails after adding bridge files, move provider code to `pkg/factorysessionexecution/livechild` and consolidate fixture tests rather than adding root package files; avoid importing `factorysessionexecution` from `livechild` tests (import cycle).
- Durable `GET /factory-sessions/{session_id}` returns `FactorySessionDurableReadModel`; normalize into shared `FactorySession` runtime shape in `ui/src/api/factory-sessions/normalize-session-get.ts` before the factory-session detail hook renders summary fields.
- Durable JavaScript inspection detail loads dispatch summaries through `ui/src/api/factory-sessions/api-durable-inspection.ts` (`listFactorySessionDispatches`) and merges them into `FactorySession.runtime.dispatches` in `use-factory-session-detail.ts`; map durable result reads with `getFactorySessionDurableResults` plus `normalize-durable-inspection.ts` when session GET lacks `resultSummary` artifact refs.
- Customer-facing runtime/orchestrator/script status labels for factory-session detail live in `ui/src/features/factory-session-detail/messages/factory-session-detail.ts` and format through `messages/factory-session-runtime-display.ts` to satisfy `check:localized-copy`.
- Factory session detail loading, missing, and error states use the same `StatusNotice` pattern as provider session detail: `AlertPanel` with `role="status"` for loading/not-found and `role="alert"` with `tone="danger"` for API failures.
- Durable JavaScript website inspection deferred follow-ups (dispatch drilldown, artifact drilldown, lifecycle controls UI, event replay, live-provider fields, real-backend E2E) belong in `docs/internal/development/plans/dynamic-workflows/follow-up-cell-website-session-inspection-deferred.md`.
- Storybook browser verification for factory-session detail uses `tags: ["test"]` on success and non-success stories; not-found play functions must `findByText` for the final message because loading and missing both use `role="status"`.
