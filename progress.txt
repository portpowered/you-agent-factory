## Codebase Patterns
- Run `make generate-api` after OpenAPI schema edits; `make api-smoke` validates bundle + drift.
- Work content contract tests live in `pkg/api/contracttests/openapi_contract_surface_test.go`.
- File-backed API validation for `content` is in `pkg/api/handlers_common.go` (`validatedRawFileContentPart`).
- Submit file items use `SubmitWorkFileItemCommonFields.yaml` and validate in `handlers_work_write.go`.
- `pkg/workcontent/urlvalidate.go` centralizes supported URL schemes (`file`, `http`, `https`, `data`) for API validation.
- Generated `WorkImageContentPart` / audio / binary use `Url` (required) and optional deprecated `File` pointer types.
- `pkg/workcontent/materialize` owns dispatch-time URL resolution: `MaterializeContentURL`, SSRF guard, bounded remote/data temps, `DispatchCache` for per-dispatch reuse.
- Remote failures use `media url inaccessible`; local missing uses `media url not readable`; SSRF uses `media url not allowed` with `(ssrf)`.
- `workcontent.FilesystemPathToContentURL` and `NormalizeFileBackedContent` map legacy `file`-only parts to `url` at ingest; canonical content keeps `url` only.
- Stage API returns `url` as `file://` absolute path; structured submit resolves staged bytes to the same canonical `url` (not `File`).
- `workcontent.ResolveDispatchContentURL` joins legacy relative `file://host/path` URLs against Codex `WorkingDirectory` before materialization.
- Codex `codexImageArgs` materializes `content[].url` via `materialize.DispatchCache` in `ScriptWrapProvider.Execute`; use `WithMaterializeOptions` in tests for httptest URLs.
- `pkg/workcontent/materialize/testdata/url_materialization_cases.json` + `LoadURLMaterializationCorpus()` drive regression cases; T9 WORK_REQUEST wire test lives in `pkg/factory/events/event_history_work_content_url_test.go`.
- Dashboard submit-work stores `response.url` from stage on draft file items; `buildStructuredSubmitItems` sends that canonical `url` plus `stagedFileRef` (not `file://staged/` placeholders).
- `describeWorkContentPart` in `ui/src/features/work-content/lib` derives human-readable labels from `url` (basename for `file://` paths, hostname for host-only `file://` URLs) when deprecated `file` is absent.
