## Codebase Patterns
- Providers owns provider-native command construction and validation; Workers shapes requests and consumes provider-neutral results.
- External process effects are injected through `edges.Edges.ProviderCommandRunner` and functional flows are built through `root.BuildProcess`.
- Provider execution requests are value contracts; new scalar execution facts must be copied at each Worker-to-Provider request construction boundary.
- Provider-specific command effects can be selected with an explicit Providers wire option while the shared platform runner remains available to existing adapters.
- Worker-authored native limits are parsed at the workstation boundary into provider-neutral execution metadata so adapters can apply their own defaults without importing worker-definition types.
- Focused Go tests live beside the owning package, while user-visible cross-service behavior belongs under `tests/functional/<domain>/...`.
- Provider stream parsers use a bounded line buffer sized for the largest recorded media trace and select only the terminal provider-authored result.
- Provider-native numeric usage facts are emitted as explicit metadata strings; token-shaped usage keys must be allowlisted in both provider normalization and public safe-diagnostics projections.
- Structured provider contracts are normalized to JSON content at the Provider boundary; the Worker owns authored-schema validation and task-level verdict semantics.
- Command effects advertise their native output format in effect metadata so strict print contracts can coexist with legacy PTY compatibility effects.
- Operator-only external smoke tests gate before executable discovery and use root.BuildProcess with an empty edge set; ordinary functional lanes inject only command-runner effects and never inherit the live gate.
- Cross-platform filesystem permission tests must account for Windows mode-bit semantics while retaining strict POSIX assertions; Windows protection is provided by ACLs rather than POSIX permission bits.
- Compare repository-wide quality-check output with the current base before attributing legacy findings; keep newly added Go tests within the backend-size limits by extracting case assertions into helpers.
