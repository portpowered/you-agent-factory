## Codebase Patterns
- When a UI branch cherry-picks OpenAPI that removes `POST /factories` and adds `SaveFactoryForSessionRequest`, run `make generate-api` and land matching backend from `ralph/session-factory-save-modes` (`pkg/service/factory_editable_definition.go` session save section, `pkg/api/handlers.go`, contract tests)—UI-only codegen fails `make api-smoke` and breaks `pkg/api` compile until those handlers ship.
- `pkg/service` has a 15 hand-maintained Go file cap—after adding session factory save modes, fold `factory_session_save.go` into `factory_editable_definition.go` and session save tests into `factory_test.go` (both already carry `pkgmaintcheck:ignore-file-lines`) instead of adding standalone `factory_session_save*.go` files.
- `getCurrentFactoryDocument` / `saveCurrentFactoryDocument` delegate to `getSessionFactory` / `saveSessionFactory`; map `SessionFactoryAPIError` (including `NETWORK_ERROR`) back to `CurrentFactoryDefinitionError` with editor-facing messages; `SaveCurrentFactoryInput.baseVersion` still becomes `factory.version` on the wrapped PUT body only. `saveCurrentFactoryDocument` always sends explicit `mode: "REPLACE_CURRENT"` on editor and replace-style import saves; story 005+ import create paths call `saveSessionFactory` with `UPSERT_NAMED_AND_ACTIVATE` directly.
- Session factory GET/PUT lives in `ui/src/api/session-factory/api.ts`: `getSessionFactory(sessionID)` and `saveSessionFactory({ sessionID, mode?, factory })` use `currentFactorySessionPath` + `transport.ts`; PUT body is `{ mode?, factory }` per `SaveFactoryForSessionRequest` (omit `mode` for server default `REPLACE_CURRENT`); normalize responses via `normalizeFactoryDefinition`.
- Human-mode `you submit` success stdout is formatted in `pkg/cli/submit/human_output.go` via `writeHumanSubmitSuccess`: lines for `Submitted: <name> (<workTypeName>)`, `traceId`, optional `workId`, then `Verify: you work show <work-id>` or fallback `workId was not returned; verify with:` + `you work list --name <name>`; use `submitResponseString` for API pointer fields with request fallbacks; httptest proof in `TestSubmit_HumanStdoutIncludesWorkMetadataAndShowHint` and `TestSubmit_HumanStdoutFallsBackToWorkListWithoutWorkId`.
- `--json` submit success uses `pkg/cli/submit/json_output.go` (`SubmitSuccessResult` / `writeJSONSubmitSuccess`): emit `workId` (pointer, omitted when absent), `name`, `workTypeName`, `traceId`, `sessionId` (API field, else `clidiag.SessionLabel`, else `sessionpath.DefaultFactorySessionID`), and `endpointPath` from `sessionpath.ScopedPath`; proof in `TestSubmit_JSONStdoutEmitsStableSuccessEnvelope` and `TestSubmit_JSONStdoutEmitsSessionScopedEndpointPath`.
- Submit failure surfaces live in `pkg/cli/submit/error_output.go` (`submitFailureError`): transport errors as `factory not reachable at <url>` with empty stdout; non-201 responses as `submission failed (<status>): <message>` from `ErrorResponse.message` or a bounded raw-body preview (`submitErrorBodyPreviewLimit` = 200 runes/bytes); optional `workId=<id>` suffix from best-effort JSON parse; proof in `TestSubmit_FactoryNotRunning`, `TestSubmit_ServerError`, `TestSubmit_NonJSONErrorBodyUsesBoundedPreview`, `TestSubmit_ErrorIncludesWorkIdWhenPresent`, and `TestSubmit_JSONModeDoesNotEmitSuccessOnFailure`.
- Extend `SubmitWorkResponse` in `api/components/schemas/api/SubmitWorkResponse.yaml`, regenerate via `make generate-api` (Go + UI), populate `interfaces.WorkRequestSubmitResult` from `requests.WorkRequestSubmitResultFromNormalized` after normalization in engine/mock factory, and map through `submitWorkResponseFromResult` in `pkg/api/submit_work_items.go` (not a separate `submit_response.go`—`pkg/api` has a 15-file cap) in both `SubmitWork` (`factorysessions.DefaultSessionID`) and `SubmitWorkBySessionId` (path param); assert `workId`, `name`, `workTypeName`, `traceId`, `requestId`, `accepted`, and `sessionId` in `server_submit_work_test.go` and session scoping tests.
- Session-scoped PNG import activation uses `activateImportedFactoryForSession` in `ui/src/api/named-factory/api.ts`: replace confirm GETs current factory, preserves session `name`, PUTs `REPLACE_CURRENT` via `saveCurrentFactoryDocument` with incremented `version`; create-new-named PUTs `UPSERT_NAMED_AND_ACTIVATE` via `saveSessionFactory` with dialog `createFactoryName`, omitting `factory.version` for newly allocated names and including version only when upserting a known existing name (including current session factory). Map `CurrentFactoryDefinitionError` / `SessionFactoryAPIError` into `NamedFactoryAPIError`; never `POST /factories`. `useFactoryImportActivation` accepts full `FactoryImportConfirmInput` (`choice`, `createFactoryName`, `existingFactoryNames`, `value`).
- Non-default session import isolation proof lives in `tests/functional/runtime_api/factory_transformation/api_current_factory_put_test.go` (`TestCurrentFactoryPUT_NonDefaultSessionImportIsolatesDefaultFactoryAndMaterializesBundledFiles`): `openNamedFactorySession` + `saveCurrentFactoryForSession` with imported-style bundled payload, assert session GET readback, unchanged default session/`alpha` on-disk config, and bundled files materialized only under `rootDir/<session-factory-name>/`.
- Dashboard import threads `useDashboardSessionStore.selectedSessionID` through `DashboardBento` → `useCurrentActivityImportController` → `useFactoryImportActivation({ sessionID })`, which defaults to `activateImportedFactoryForSession` so tab switches before confirm retarget activation without reload (mirror `useCurrentFactoryExport` session routing).
- `App.import.test.tsx` mocks `/factory-sessions/{session_id}/factory` by HTTP method (GET with `version`, then versioned PUT) and asserts no `POST /factories`; use `createDeferredPromise` from `app-shell-export-test-utils` to observe `Activating factory...` submitting state before resolving PUT.
- Import confirm dialog (`dashboard-import-preview-dialog.tsx`) defaults to replace-current, uses a fieldset/radio group for create-new-named, derives suffixed create names via `allocateImportCreateFactoryName`, and confirms with `FactoryImportConfirmInput` including `existingFactoryNames` for activation; thread `currentSessionFactoryName` from `snapshot.factory?.name` through `DashboardBento` and graph-editor dialog seams; assert PUT `mode` in `App.import.test.tsx` and `factory-import-second-session.integration.test.mjs`.
- Inline single-use workflow-activity layout class strings directly on JSX in `workflow-activity-bento-card.tsx`; assert the graph panel shell via the viewport region’s `section[aria-labelledby]` parent in `workflow-activity-bento-card.test.tsx` (contains `relative`, `h-full`, `min-h-0`, `min-w-0`).
- Parse worker/workstation `openCodeAgent` through `pkg/config/agents_config.go` with `validateOpenCodeAgentInFrontmatter` (rejects explicit empty or whitespace-only values), merge via `applyWorkerRuntimeExecution` / `applyWorkstationRuntimeIdentity`, and resolve dispatch precedence with `interfaces.ResolveOpenCodeAgent(workstation, worker)`.
- Forward resolved OpenCode agent on `interfaces.ProviderInferenceRequest.OpenCodeAgent` from `pkg/workers/executor/agent.go` `inferenceRequestForExecutionRequest` only when `ModelProvider` is `opencode`; lookup workstation via `runtimeConfig.Workstation(inferenceWorkstationType(request))` and leave the field empty for other providers.
- Append `opencode run --agent <name>` in `openCodeProviderBehavior.BuildArgs` when `req.OpenCodeAgent` is non-empty, placing `--agent` after `--model` and before `--session`; empty agent leaves today's `opencode run` arg shape unchanged.
- Record configured OpenCode agents as `opencode_agent` in provider request metadata from `workDiagnosticsForInferenceRequest` in `pkg/workers/executor/diagnostics.go` and `pkg/workers/provider/helpers.go` only when `OpenCodeAgent` is non-empty; allowlist via `isSafeProviderMetadataKey` in `pkg/interfaces/safe_diagnostics.go`.
- Reject non-empty resolved `openCodeAgent` when `interfaces.ResolveRunnerSelection(...)` is not `opencode` via `interfaces.ValidateOpenCodeAgentForRunnerSelection(...)` from `pkg/service/factory_build.go` `validateConfiguredWorkstationRunners` before worker load; error text includes `openCodeAgent`, agent name, required runner `opencode`, and resolved runner ID.
- Header-only structured submit-work (`name`, `workTypeName`, `items: []`) is accepted in `pkg/api/submit_work_items.go` via empty-array early returns in `validateSubmitWorkItemsField` and `submitWorkItemsToContent`; API proof lives in `TestSubmitWork_AcceptsHeaderOnlyStructuredSubmitWork` and `TestGeneratedAPIIntegrationSmoke_SubmitWorkItemsAcceptHeaderOnlyStructuredSubmission`.
- Dashboard header-only submit proof belongs in `submit-work-widget.test.tsx` (`completes header-only submission when the default text item is blank`) and the empty-payload segment of `App.follow-up-submit.test.tsx`; assert POST body `items: []`, success trace status copy, and absence of submit error fallback.
- Hide internal `__system_time` factory graph nodes with `filterFactoryGraphTopologyForCustomerDisplay` in `ui/src/features/factory-graph-editor/lib/factory-graph-customer-display.ts`; reuse `systemTime.ts` constants/predicates and apply the filter at graph render boundaries (layout/projection) before seeding nodes or edges.
- Apply customer-display filtering in `projectFactoryGraphToReactFlow` only; keep `buildFactoryGraphTopologyFromDefinition` and draft-validation topology unfiltered so canonical factory data and editor mutations stay complete.
- Second-tab PNG import browser proof lives in `ui/integration/factory-import-second-session.integration.test.mjs`: open a non-default session via the Factory Session dialog, export then import on that tab, and track `onSaveCurrentFactory` for the non-default `sessionID` with `mode: "REPLACE_CURRENT"`; use `expect.poll` for PUT completion because submitting-state copy can flash too quickly in Playwright.
- Legacy `createFactory` and dashboard `POST /factories` were removed from `ui/src/api/named-factory/api.ts`; import activation uses session PUT modes only. Browser/integration harnesses stub `/factory-sessions/{session_id}/factory` GET/PUT via `onSaveCurrentFactory`—do not reintroduce `onActivateFactory` or `/factories` POST handlers.
- Session factory operator-facing error copy lives in `ui/src/api/session-factory/operator-errors.ts` (`sessionFactoryOperatorErrorMessages`, `resolveSessionFactoryAPIErrorMessage`); HTTP failures apply it at throw time in `api.ts`. `current-factory-definition` only remaps transport-shell messages (network, rejected request, invalid response) to editor copy; `named-factory` passes through `SessionFactoryAPIError.message`. Import preview `errorByCode` for `STALE_FACTORY_VERSION`, `FACTORY_NOT_IDLE`, `INVALID_FACTORY`, and `INVALID_FACTORY_NAME` should import the same English strings from `sessionFactoryOperatorErrorMessages`.
- Register new packaged `you docs` topics in the single `topicDocuments` table in `pkg/cli/docs/docs.go` with canonical name, description, `displayOrder`, path, and optional aliases together so `SupportedTopics()`, index output, and unsupported-topic errors stay aligned.
- Keep `docs/reference/*.md` and `pkg/cli/docs/reference/*.md` synchronized when adding customer-facing packaged topics; embedded markdown is loaded from `pkg/cli/docs/reference/` via `//go:embed`.
- When a new canonical topic is added, update hardcoded topic-order assertions in `pkg/cli/docs/docs_test.go`, `pkg/cli/root_docs_test.go`, and `tests/functional/smoke/cli_docs_smoke_test.go` unsupported-topic error expectations.
- When trimming `authoring-factories` after new topics land, point readers at `you docs mock-workers` and `you docs record-replay` and update `TestMarkdown_AuthoringFactoriesReturnsRawAuthoredMarkdown` markers away from removed deep-dive strings.
- Register `relationships` at `displayOrder` 28 immediately after `guards` (27); relationships content adapts `batch-inputs.md` relation sections and `parent-aware-fan-in.md` with `SPAWNED_BY` called out as runtime/template-only, not batch-authored.
- Story 003 index assertions belong in `root_docs_test.go` and `cli_docs_smoke_test.go` immediately after `record-replay` lines; smoke topic tests can use `absent` for `../internal/development/...` paths when replacing packaged cross-links.
- Do not `cp` `pkg/cli/docs/reference/config.md` or `templates.md` onto `docs/reference/` — the layout-tree guides diverge from embedded packaged topics; apply cross-link edits to both trees separately.
