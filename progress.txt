## Codebase Patterns
- CLI workflow source validation loopback uses `pkg/apisurface/factory_workflow_validation.go` (`BuildFactoryWorkflowValidation`, `FactoryWorkflowValidationResultFromPreview`) on top of `BuildFactoryPreview`; `you workflow validate` lives in `pkg/cli/workflow/validate.go` with shared source flags via `SourceConfig` in `request.go` (including optional `--args-schema` and `--requested-policy`). JSON uses generated `WorkflowSourceResolution` plus `blockingDiagnostics` (`[]WorkflowDiagnostic`); denied capabilities from READ_ONLY policy preview are informational, not blocking. Human failure output labels a `Blocking diagnostics:` section; JSON failure emits the validation result then exits non-zero.
- CLI durable Factory Session listing loopback uses `you session list --scope live|persisted|all` in `pkg/cli/session/list.go` with durable rows from `factorysessionexecution.FakeService` (`NewFakeServiceFromContractFixtures`, catalog `fixtures.ContractFixtureCatalogRelativePath`) merged through `ApplySessionListScope` and `factorysession.ListSessionsResponseToAPI`; `scope=live` keeps the legacy HTTP `GET /factory-sessions` workspace table. Reject unsupported scopes via `NormalizeListSessionsRequest` before HTTP/durable calls; provider and scope-validation failures keep stdout empty for `--json`. Human durable output uses a `Factory Sessions (durable):` table; JSON uses the same generated `ListFactorySessionsResponse` / `FactorySessionDurableSummary` shapes (no CLI-only list schema). Prove JSON parity by marshaling `factorysession.ListSessionsResponseToAPI(ApplySessionListScope(...))` in `list_test.go`; inject `ListConfig.DurableLister` in tests.
- CLI workflow source input validation rejects missing/conflicting `--kind`/`--value`/`--inline` combinations in `pkg/cli/workflow/request.go` (`validateSourceConfig`) before `DefaultContext` or preview validation; command errors keep stdout empty even when `--json` is set. JSON blocking-validation failures still emit the structured result then exit non-zero.
- Published Factory Session fixture scenario IDs and stable projection hashes live in `pkg/factorysessionexecution/fixture_catalog.go` (`PublishedFixtureScenarios`, `FixtureScenarioIdentityFromScenario`, `FixtureScenarioProjectionHash`); contract JSON remains in `pkg/api/testdata/durable-session-contract-fixtures.json` and loads through `LoadFakeScenariosFromContractFixtures`.
- Use `ContractFixtureCatalogRelativePath` when downstream cells need the repository-relative catalog path; prove stable identity with `fixture_catalog_test.go` golden projection hashes rather than recomputing ad hoc in each consumer package.
- Built-in recoverable interrupted JavaScript session `javascript-interrupted-recoverable` is appended by `LoadFakeScenariosFromContractFixtures` even though it is not in the JSON catalog.
- Prove FakeService start/list/read/result behavior against `PublishedFixtureScenarios` in `start_list_read_result_test.go`; use `ProjectedResultReadHash` and `SyncStartResultHash` for golden result digests instead of ad hoc field comparisons.
- CLI compatibility wording: keep `you workflow validate` primary and `you workflow preview` compatibility-only in `pkg/cli/root.go`; parent `you session` help documents durable Factory Session listing in `pkg/cli/root_work.go`. Prove command help and human-output vocabulary with `fixtures.ForbiddenFixtureVocabularyTerms()` in `pkg/cli/root_workflow_session_terminology_test.go`.
