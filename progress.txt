## Codebase Patterns
- Use `workflowruntime.Hooks.NewChildExecutor` with `ChildRecordSink` to swap fake vs `live-provider` child execution without changing workflow JS source.
- Select live child execution via `StartRequest.Runtime.ChildExecutorMode = "live-provider"` and configure `JavaScriptRuntimeServiceConfig.Provider`.
- Durable dispatch inspection for JavaScript children flows through `ProjectRuntimeExecutionRecords` into `DispatchSummary` plus `DispatchJavaScriptProjection.ExecutionMode`.
- `ProjectRuntimeExecutionRecords` also projects ordered `DispatchStatusTransitions` per dispatch ID and child output artifacts from completed `ChildDispatchRecord.ArtifactRef`.
- Failed child dispatches persist `FailureReason`, `FailureMessage`, and optional `FailureErrorClass` on terminal `ChildDispatchRecord` rows; `dispatchFailureDetailFromChildRecord` maps them to `DispatchFailureDetail`.
- `projectRuntimeSessionState` applies `applyRuntimeExecutionRecordProjection` on workflow failure when `outcome.Records` is non-empty so failed child dispatches remain inspectable.
- `workflowruntime.Run` attaches emitted runtime records to terminal promise-rejection and invalid-result failures, not only synchronous script errors.
- `GetDispatch` on the JavaScript runtime service exposes `StatusTransitions` and `ArtifactIDs` from the runtime projection state.
- Default JavaScript runtime durable sessions keep fake child execution when no runtime override is provided.
- Select explicit fake child execution via `StartRequest.Runtime.ChildExecutorMode = "fake"` even when the service default is `live-provider`; request-level mode wins over `JavaScriptRuntimeServiceConfig.ChildExecutorMode`.
- Record deferred CLI/MCP/website follow-ups in `docs/internal/development/plans/dynamic-workflows/follow-up-cell-live-provider-dispatch-bridge-deferred.md` instead of widening the bridge lane.
