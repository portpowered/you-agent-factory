## Codebase Patterns
- Normalize durable Factory Session CLI start flags through `pkg/cli/sessionexecution.NormalizeStartRequest` → `pkg/apisurface/factorysession.StartRequestFromCLI` → `factorysessionexecution.NormalizeStartRequest`; render deterministic human/JSON failures with `sessionexecution.WriteExecutionError`.
- Inline workflow CLI source text reuses `invocations.ResolveTextInput` ownership rules; explicit `--factory`, `--workflow`, and `--workflow-file` selectors are mutually exclusive.
- Published Factory Session fixture scenario IDs and stable projection hashes live in `pkg/factorysessionexecution/fixture_catalog.go` (`PublishedFixtureScenarios`, `FixtureScenarioIdentityFromScenario`, `FixtureScenarioProjectionHash`); contract JSON remains in `pkg/api/testdata/durable-session-contract-fixtures.json` and loads through `LoadFakeScenariosFromContractFixtures`.
- Use `ContractFixtureCatalogRelativePath` when downstream cells need the repository-relative catalog path; prove stable identity with `fixture_catalog_test.go` golden projection hashes rather than recomputing ad hoc in each consumer package.
- Built-in recoverable interrupted JavaScript session `javascript-interrupted-recoverable` is appended by `LoadFakeScenariosFromContractFixtures` even though it is not in the JSON catalog.
- Prove FakeService start/list/read/result behavior against `PublishedFixtureScenarios` in `start_list_read_result_test.go`; use `ProjectedResultReadHash` and `SyncStartResultHash` for golden result digests instead of ad hoc field comparisons.
- Wire mock-backed synchronous CLI starts through `sessionexecution.RunSync` and `you workflow run`; render human/JSON via `factorysession.SyncStartResponseToAPI`; default to contract-fixture `FakeService` when no service is injected.
- `FakeService.StartSync` stores the first sync start payload on the start replay record so request-id replays return the original fixture sync response instead of re-projecting from session state.
- Wire mock-backed asynchronous CLI starts through `sessionexecution.RunAsync` and `you workflow start`; poll status through `RunStatus` and `you workflow status <session-id>`; async JSON adds `requestId` and shared partial `GetResult` `resultAvailability` atop `FactorySessionExecutionResponse`.
- `FakeService.StartAsync` stores the first async start payload on the start replay record so request-id replays return the original fixture async response instead of re-projecting from session read state.
- Wire mock-backed durable result reads through `sessionexecution.RunResult` and `you workflow result <session-id>`; normalize `--mode` / `--include-artifacts` via `ResultRequestFromCLI`; render `FactorySessionResult` through `ResultResponseToAPI`; return `ResultOutcomeError` for `NOT_READY`, `UNAVAILABLE`, and `FAILED_WITH_PARTIAL` after writing human/JSON output so automation gets non-zero exits without `SESSION_NOT_FOUND`.
