## Codebase Patterns
- JavaScript workflow runtime lives in `pkg/orchestrators/javascript/runtime`; use `Run(ctx, Request, Hooks)` with explicit source, args, metadata, and policy rather than package-global execution state.
- Wrap workflow source in an IIFE before `goja` execution so top-level `return` statements work: `(function(){\n` + source + `\n})()`.
- Run pre-execution validation on the same IIFE-wrapped executable source via `workflowvalidation.Validate`, then remap diagnostics back to authored lines by subtracting one from reported line numbers.
- Pre-execution failures return `WORKFLOW_RUNTIME_PRE_EXECUTION_INVALID` with `[workflow.source.*]` validation codes embedded in the message; result/artifact hooks must not run.
- Route successful terminal values through `workflowresult.ValidateTypedValue` and `workflowresult.ProjectPrimaryResult` from `pkg/orchestrators/javascript/result`.
- `workflow.final` is supported on the runtime `workflow` global; when both `workflow.final` and a returned value are present, `workflow.final` wins (`runtimeGlobals.terminalValue`).
- Use `github.com/dop251/goja@v0.0.0-20251201205617-2bb4c724c0f9` with Go 1.24; newer goja releases require Go 1.25+.
- Fixture-backed runtime tests belong in `pkg/orchestrators/javascript/runtime/testdata/*.workflow.js` with tests in `runtime_test.go`.
- Execution failures use `WORKFLOW_RUNTIME_SCRIPT_ERROR` (extract JavaScript `Error.message` via `javascriptExceptionMessage`, not `fmt.Sprint` on exported Error objects) or `WORKFLOW_RUNTIME_UNRESOLVED_FINAL`; result/artifact hooks must not run on failure.
- Cancellation and timeout use `watchContext` + `vm.Interrupt`; map `context.Canceled` to `WORKFLOW_RUNTIME_CANCELED` and `context.DeadlineExceeded` to `WORKFLOW_RUNTIME_TIMEOUT` via `contextTerminationOutcome`; use `busy-loop.workflow.js` for bounded cancel/timeout tests without sleeps.
- Forbidden host-access patterns from `workflowvalidation.Validate` map to `WORKFLOW_RUNTIME_DENIED_CAPABILITY` at the runtime boundary (not `WORKFLOW_RUNTIME_PRE_EXECUTION_INVALID`); default goja globals are only `args`, `meta`, and `workflow.final`.
- Dynamic `import("module")` parses as `CallExpr` with `*js.LiteralExpr` callee (`TokenType=import`); extend `callCalleeName` to read literal `Data`, not only `IdentifierToken`.
