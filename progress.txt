## Codebase Patterns
- Guard list rows in `EditableConfigurationWorkstationGuardsField` use `useStableWorkstationGuardRowKeys` so React keys do not depend on `formatWorkstationGuardSummary(guard)` (which embeds live `inputKey`).
- `MATCHES_FIELDS` `matchConfig.inputKey` uses `MonacoGuardSelectorEditor` (`data-monaco-editor="workstation-guard-selector"`) with static completions from `buildWorkstationGuardSelectorCompletionItems()` (`.Name`, `.WorkID`, `.Tags["key"]`); do not reuse prompt-template completion providers.
- When testing bracket-heavy selector typing with `@testing-library/user-event`, prefer incremental `fireEvent.change` loops over `user.type`/`user.keyboard` because `[` and `"` are parsed as key descriptors.
- `MonacoGuardSelectorEditor` does not accept a `diagnostics` prop or set Monaco model markers; save-time guard validation stays in `validateEditableWorkstationGuardDraft` / `validateEditableWorkstationDraft` only. Vitest Monaco mock exposes `data-monaco-marker-count` / `data-monaco-marker-messages` on the wrapper for asserting zero markers on custom selector text.
- `applyEditableWorkstationDraft` copies `draft.guards` verbatim onto the workstation; `normalizeFactoryDefinition` and `saveFactoryForSessionDocument` preserve `matchConfig.inputKey` without trimming (trim is validation-only in `workstation-editable-validation.ts`).
