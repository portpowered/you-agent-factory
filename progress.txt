## Codebase Patterns
- Use `workflowruntime.Hooks.NewChildExecutor` with `ChildRecordSink` to swap fake vs `live-provider` child execution without changing workflow JS source.
- `ChildExecutor.Execute` accepts the bounded workflow `context.Context` from `workflowruntime.Run`; live provider bridges must pass it through to `Provider.Infer` instead of `context.Background()`.
- Select live child execution via `StartRequest.Runtime.ChildExecutorMode = "live-provider"` and configure `JavaScriptRuntimeServiceConfig.Provider`.
- Durable dispatch inspection for JavaScript children flows through `ProjectRuntimeExecutionRecords` into `DispatchSummary` plus `DispatchJavaScriptProjection.ExecutionMode`.
- `ProjectRuntimeExecutionRecords` also projects ordered `DispatchStatusTransitions` per dispatch ID and child output artifacts from completed `ChildDispatchRecord.ArtifactRef`.
- Failed child dispatches persist `FailureReason`, `FailureMessage`, and optional `FailureErrorClass` on terminal `ChildDispatchRecord` rows; `dispatchFailureDetailFromChildRecord` maps them to `DispatchFailureDetail`.
- `projectRuntimeSessionState` applies `applyRuntimeExecutionRecordProjection` on workflow failure when `outcome.Records` is non-empty so failed child dispatches remain inspectable.
- `workflowruntime.Run` attaches emitted runtime records to terminal promise-rejection and invalid-result failures, not only synchronous script errors.
- `GetDispatch` on the JavaScript runtime service exposes `StatusTransitions` and `ArtifactIDs` from the runtime projection state.
- Default JavaScript runtime durable sessions keep fake child execution when no runtime override is provided.
- Select explicit fake child execution via `StartRequest.Runtime.ChildExecutorMode = "fake"` even when the service default is `live-provider`; request-level mode wins over `JavaScriptRuntimeServiceConfig.ChildExecutorMode`.
- Record deferred CLI/MCP/website follow-ups in `docs/internal/development/plans/dynamic-workflows/follow-up-cell-live-provider-dispatch-bridge-deferred.md` instead of widening the bridge lane.
- When `make pkg-file-count` fails after adding bridge files, move provider code to `pkg/factorysessionexecution/livechild` and consolidate fixture tests rather than adding root package files; avoid importing `factorysessionexecution` from `livechild` tests (import cycle).
- CLI workflow execution defaults to fixture-backed fake service; select real backend with `--execution-provider javascript-runtime`, `--project-root`, and `--child-executor-mode live-provider`. `factorysessionexecution.SmokeLiveChildProvider()` supplies deterministic live-child smoke without MCP host startup. Pass `Runtime.ChildExecutorMode` through `CLIStartInput.Runtime` in `factory_session_execution_cli.go`. `RunDispatches` human output includes provider id, provider session refs, and output artifact ids; `RunArtifacts` human output includes dispatch linkage when present. JavaScript runtime terminal sessions persist under `{projectRoot}/.you-agent-factory/durable-sessions/` so separate CLI processes reload status/result/dispatch/artifact reads through `runtimepersist` without a shared in-memory `Service`.
- When backend-size limits block oversized CLI test files, extract assertion helpers and consolidate live-provider tests into `live_provider_test.go`; merge `error_test.go` into `normalize_test.go` to stay within the 15-file `pkg/cli/sessionexecution` ceiling.
- Select runtime-backed MCP serve via `you mcp serve --runtime`, which wires `factorysessionexecution.NewExecutionService(ExecutionProviderJavaScriptRuntime, ServiceConfig{ProjectRoot})` in `pkg/cli/mcp/serve.go`; default serve remains fixture-backed and rejects combining `--runtime` with `--fixture-catalog`.
- Runtime-backed MCP serve stdio smoke lives in `pkg/cli/mcp/serve_runtime_smoke_test.go` via `RunServe` with `ServeConfig{RuntimeBacked: true, ProjectRoot}` (no injected service), reusing the stdio client harness from `serve_smoke_test.go` and INLINE_WORKFLOW fixtures to prove live durable execution instead of the fixture catalog.
- Runtime-backed MCP async start/status/result tests live in `pkg/mcp/factorysession/runtime_execution_test.go` via `NewClientWithService(NewExecutionService(ExecutionProviderJavaScriptRuntime, ...))` and INLINE_WORKFLOW fixtures; cancel busy-loop sessions through direct service `Cancel` for cleanup.
- Customer MCP docs in `docs/reference/mcp.md` and `docs/reference/mcp-hosts.md` document fixture-backed default vs `you mcp serve --runtime`, keep Factory Session vocabulary, and record stdio-only scope boundaries (no website inspection, HTTP/SSE, or broader host-matrix expansion); update `cli_docs_smoke_test.go` and `pkg/cli/docs/docs_test.go` markers when changing packaged doc sections.
