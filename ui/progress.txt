## Codebase Patterns
- When `make backend-size` fails on taxonomy PRs, split oversized `pkg/config/openapi_factory.go` helpers into sibling files (e.g. `openapi_factory_retired_boundary.go`) and move large contract-test case tables into dedicated `*_test.go` files or smaller helper functions under the 100-line function limit.
- Storybook editable-configuration browser verification must scope worker fields with `workerConfigurationSection` (`heading.closest("section")`), not `heading.parentElement` (the header row only); assert selected worker type via the `Worker type` combobox text content.
- Storybook editable-configuration flows need `snapshot.factory.version` (via `buildEditableConfigurationDashboardSnapshot`) or `resolveCurrentFactoryDocumentFromSnapshot` stays loading; merge topology workstations with Review fixture overrides from the mocked session factory document.
- Cross-feature imports of worker/workstation taxonomy helpers must go through `ui/src/features/current-factory-definition/public/` (re-exported from `worker-workstation-taxonomy.ts`), not `lib/worker-workstation-taxonomy`.
- Worker taxonomy: author new public names in `api/components/schemas/data-models/WorkerType.yaml`, canonicalize legacy aliases in `pkg/interfaces/public_factory_enums.go`, and project public values to internal runtime identifiers via `InternalRuntimeWorkerTypeFromPublic` / `PublicWorkerTypeFromInternalRuntime` through `pkg/config/factory_config_mapping_internal.go`.
- Workstation taxonomy: author new public names in `api/components/schemas/data-models/WorkstationType.yaml`, canonicalize legacy aliases in `pkg/interfaces/public_factory_enums.go`, and project via `InternalRuntimeWorkstationTypeFromPublic` / `PublicWorkstationTypeFromInternalRuntime` (with worker-type and poller-kind context) through `pkg/config/factory_config_mapping_internal.go` and `workstationTypePtrIfNotEmpty` in `pkg/config/factory_config_mapping.go`.
- Replay/generated-factory workstation projection must pass worker type into `WorkstationConfigToOpenAPIWithWorkerType` so `SCRIPT_RUN` vs `AGENT_RUN` survives merge paths.
- Worker/workstation compatibility: behavior classes and `PublicWorkerTypeForFactoryUsage` live in `pkg/interfaces/worker_workstation_compatibility.go`; validate at API boundary via `WorkerWorkstationCompatibilityTargetsFromAPI` before internal type collapse, and at structural validation via `WorkerWorkstationCompatibilityTargets`. Post-load `normalizeFactoryWorkerTypesForFactoryUsage` in `openapi_factory.go` must run after workstation normalization so legacy `MODEL_WORKER` projects to `AGENT_WORKER` vs `INFERENCE_WORKER` by usage; when one legacy worker is referenced from both agent and inference workstations, preserve `MODEL_WORKER` and accept it with normalized `AGENT_RUN` / `INFERENCE_RUN` in `workerMatchesWorkstationPublicAPI`.
- Graph add creation controls must expose the full public worker/workstation taxonomy via `FACTORY_GRAPH_ADD_WORKER_TYPES` / `FACTORY_GRAPH_ADD_WORKSTATION_TYPES`; pair add defaults with `INFERENCE_WORKER` + `DEFAULT_FACTORY_GRAPH_ADD_WORKSTATION_TYPE` (`INFERENCE_RUN`) instead of `AGENT_RUN`.
- Service runtime provider metrics must treat `MODEL_WORKER`, `AGENT_WORKER`, and `INFERENCE_WORKER` as provider-boundary workers in `pkg/service/factory_build.go`.
- Run `make generate-api` after OpenAPI enum changes; install UI deps with `npm ci` in `ui/` if `openapi-typescript` is missing in a fresh worktree.
- Docs/examples taxonomy: teach `INFERENCE_*`, `AGENT_*`, `SCRIPT_*`, and `POLLER_*` as primary public names in `docs/reference/` and `examples/`; keep legacy `MODEL_WORKER`, `MODEL_INVOKE`, `MODEL_WORKSTATION`, and `HOSTED_WORKER` in compatibility sections; update `tests/functional/smoke/cli_docs_smoke_test.go` markers when adding new packaged-topic vocabulary.
